# simple-mindmap 技术方案（v1 草案）

---

## 一、目标与不可让步项

| 要求（用户原话） | 本方案的实现 |
|---|---|
| **卸载插件不破坏数据** | 所有数据都在 **md 文件里**（一个 fenced 代码块），插件卸载后文档完好、内容仍可读；插件不产生任何私有格式文件 |
| **尽可能少依赖插件本身** | 导图内容 = **人类可读的 markdown 大纲文本**（不是 JSON），任何编辑器/其他插件都能读；离开本插件仍是一份完整文档 |
| **速度快** | 插件 `onload` **不加载任何库**（< 5ms）；库（1.53 MB）在**首次打开导图时**才动态加载；不打开就不付代价 |
| **不修改原始文件**（用户长期习惯） | 只在用户**显式编辑**时改写，且**逐字节保留** fence 之外的正文与 frontmatter |

**与现成插件（simple-mind-map v0.2.10）的差异化**：启动成本（现成插件库随入口加载 = 161ms / 6.58MB）、md-first 数据、砍掉 AI/协作/PDF/公式/登录。

## 二、数据格式（核心决策）

**一个代码块装全部**，文本形态的**大纲**在前、"样式"在后，用 `---` 分隔：

````markdown
## 我的图（正常笔记内容，插件不改）

```mindmap
- 中心主题
  - 分支 A
    - 叶子 1
    - 叶子 2
  - 分支 B
---
layout: logicalStructure
theme: classic13
nodes:
  分支 A: { color: "#e06c75", icon: "⭐" }
  叶子 2: { note: "补充说明" }
```

后面的笔记内容也不动。
````

**为什么这样设计**（对应你的三个顾虑）：

| 你的顾虑 | 结论 |
|---|---|
| "卸载后变成列表形式，导图效果可能差" | **结构在文本里，渲染在插件里** —— 效果不受限（布局/主题/样式都能画）；卸载后剩下的是**缩进大纲**，比 JSON 可读得多 |
| "留下的 md 可读性差、意义不大" | 大纲文本本身**有意义**（能看懂写了什么），只是没有配色；样式段是 YAML，人也能读 |
| "Bases 不是 md、Excalidraw 变 md 也看不出内容" | 本方案**反过来**：md 是唯一真源，插件只是"渲染器 + 编辑器" |

**取舍（要你知情）**：笔记里会多出一段 `mindmap` 代码块（"稍脏"，你已确认接受）；样式只覆盖**节点级 + 图层级**（布局/主题/颜色/图标），不做自由画布摆放（自由坐标会毁掉可读性）。

### md ↔ 树 的转换规则（纯函数，可单测）

**正向（文本 → 树）**
- 缩进（2 或 4 空格、Tab）决定层级；`-`/`*`/`+` 列表项为节点；
- 节点文本支持行内 markdown（**粗体**/`[[链接]]`/`*斜体*`）→ 渲染成富文本；
- 空行忽略；`\` 转义允许在节点里写 `-` 开头；
- `---` 之后是样式 YAML（缺省则用全局默认）。

**反向（树 → 文本）**
- 统一输出 `- ` + 2 空格缩进、`\n` 行尾；**同一棵树往返必须逐字节一致**（单测守）。

## 三、架构与仓库结构

```
E:\Github\simple-mindmap\
├─ main.js                 ← 可读的薄入口：注册视图/命令/设置、md 读写、md↔树转换
├─ manifest.json           ← id: simple-mindmap
├─ styles.css              ← 插件外壳样式（少量）
├─ versions.json
├─ vendor\
│   ├─ mind-map.js         ← dist/simpleMindMap.esm.min.js（1.53 MB，懒加载）
│   └─ mind-map.css        ← dist/simpleMindMap.esm.min.css（24 KB）
├─ tools\
│   ├─ test.mjs            ← md↔树、fence 定位、写入安全 的单测
│   ├─ check-id.mjs        ← 社区注册表重名检查（沿用）
│   └─ deploy.ps1          ← 部署到 E:\Dnotes
├─ docs\技术方案-2026-10-11-2240.md
├─ THIRD-PARTY-NOTICES.md  ← 上游 MIT 许可证全文 + 版本（合规必需）
├─ README.md · LICENSE(MIT) · .gitignore
```

**分工**：`main.js` 保持**可读、零依赖**（符合我的惯例）；库放 `vendor/` 且**懒加载**（你已同意为库破例）。

### 懒加载机制（**开工第一步先做 spike 验证**）

优先方案：`vendor/mind-map.js` 用构建工具转成 **CJS**（esbuild 一次转换）→ `main.js` 里 `require('./vendor/mind-map.js')`（**只在首次打开视图时执行**）。
备选：`<script type="module" src="app://local/.../vendor/mind-map.js">` 注入后取全局（受 Electron CSP 约束）。
**风险**：Obsidian 插件对相对路径 `require` 的支持需要实测；spike 失败就换备选，**不带着不确定性往下写**。

### 视图与交互（功能边界）

- **内联渲染**：注册 code block processor，`mindmap` 块在阅读/实时预览里渲染成图（只读，点击进编辑）；
- **全窗视图**：命令「把当前笔记当导图打开」→ 新标签页里渲染 + 编辑（拖拽/增删/改文字/折叠）；
- **保存**：显式保存（或视图关闭时若有改动）→ **只替换那个 fence 的行区间**，其余字节不动；
- **导出**：SVG / PNG（砍 PDF/XMind/Word）；
- **主题**：内置少量主题 + 跟随 Obsidian 亮/暗；
- **不做**：AI 生成、多人协作、公式、水印、外框、关联线、自由摆放。

## 七、需要你确认的 3 个小点

1. **代码块语言名**：用 `mindmap`（简短，但与现成插件的 `mindmap` 块可能"撞名"——若你还保留现成插件，会两个都抢；建议用 **`mindmap`**，因为你说过要卸载它）还是换个独有名如 `smmap` 以避免冲突？
2. **内联渲染默认开关**：默认**开**（笔记里直接看到图）还是默认关（只有主动打开视图才画）？我倾向**默认开**，否则"图在笔记里"的体验就没了。
3. **写回时机**：我倾向 **① 显式保存按钮 + ② 视图关闭时若有未保存改动则提示**（而不是每次按键自动写盘）—— 更安全，符合你"不打扰原始文件"的习惯。
